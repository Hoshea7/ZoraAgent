# 项目目录与会话

## 产品行为

项目目录失效时，用户可以继续查看历史、发送消息、追加问题和修改历史消息后重跑。Agent 可以讨论历史内容、使用可访问的附件及独立工具；依赖失效目录的操作需要重新关联后执行。

| 操作 | 目录失效时 |
| --- | --- |
| 查看历史、继续对话 | 正常使用 |
| 项目中新建会话或 Fork | 禁用，保留原会话与草稿 |
| 项目相对路径读写、在项目中执行命令 | 工具返回目录不可用，提示关联目录 |
| 读取已保存附件或项目外明确的可访问文件 | 保持可用，沿用原权限规则 |
| 项目菜单、编辑项目 | 正常使用 |

项目显示为灰色，新建会话图标可聚焦和悬停，提示“该项目文件夹已被删除或移动”。目录恢复后，正常刷新即可恢复可用状态。

## 项目管理

省略号菜单提供置顶、编辑项目、打开本地文件夹、移除项目。

“编辑项目”同时编辑名称与本地文件夹。修改先暂存，保存时一起提交；重新关联沿用项目和会话 ID，更新文件树与后续工具运行目录。运行中的会话结束后可以修改绑定。

“打开本地文件夹”打开项目实际目录。“移除项目”移除应用中的项目数据，本地项目文件夹及其文件保留。

## 运行规则

每轮执行区分原会话绑定与运行时目录：

- 原目录可用时，工具正常在该目录执行。
- 原目录不可用时，在会话自身的运行数据中准备独立目录，让 Runtime 能启动。它不替代项目绑定，不展示为恢复后的项目文件夹，也不用于项目文件读写。
- 本地文件工具执行前检查目录，避免将相对路径解析到临时运行目录；模型根据实际工具结果继续处理。
- 明确指向项目外的可访问文件以及附件资源仍可读取。目录检查独立于 Ask/YOLO 等授权模式。
- 下一轮原目录恢复或用户重新关联后，使用实际项目目录继续。

Pi 保留原生会话及压缩上下文，并使用本轮工作目录。Claude 在无法恢复原生会话时沿用现有产品历史恢复机制。

重新关联通过工作区操作锁串行执行。工作区索引、项目侧文件、会话索引发生写入异常时，使用临时关联记录回滚；成功后清除记录。已有运行期间不改变其目录绑定。

## 验收

- L1：来源路径解析与边界、目录工具检查、操作锁、项目编辑及草稿状态。
- L2：索引一致性、失效目录不被重建、运行目录不改变绑定、临时运行目录清理、重绑失败恢复与原生 Pi 上下文保留。
- L3 Local：目录失效置灰、新建禁用、编辑取消与保存、文件树更新、重启保持、打开文件夹、移除保留本地文件。
- L3 Provider：使用真实 Provider 生成历史；目录失效时原会话仍可回复，工具无法读取失效项目；重新关联后在原会话读取新文件并通过工具确认新工作目录。覆盖 Pi 和 Claude。
