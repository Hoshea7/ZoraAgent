# Zora 数据迁移方案

状态：目录布局 v2、历史格式升级、项目目录管理、技能异常隔离、文件附件与迁移指南已实现。Agent 协助检查、打包和准备恢复数据，目标应用退出后放入数据并重新启动。

## 产品目标

用户将完整 `.zora` 带到新设备，能够查看原有会话、打开附件和托管文件，在关联本地项目后继续工作。

首次迁入适用于尚未启动 Zora，以及已完成安装或初始配置的新设备。恢复以原设备的完整数据为准，目标已有数据保留为备份。数据位置由当前设备的用户主目录和 `ZORA_HOME` 决定。

## 换机流程

| 阶段 | 用户操作与产品行为 |
| --- | --- |
| 准备 | 在设置的“数据迁移”中打开实际数据文件夹，完整复制或压缩 `.zora`，也可复制提示词让 Zora 协助打包。副本保存在数据目录之外，建议当前任务结束后进行 |
| 传输 | 将目录或压缩包传到新设备，外部项目文件另行携带 |
| 恢复 | 核对目标数据位置并保留原数据备份。在目标应用关闭时放入完整目录，启动后自动升级已知旧格式 |
| 关联 | 项目原目录不可用时，通过“编辑项目”选择本机文件夹；暂未关联也可以查看历史 |
| 继续 | 检查历史和附件、完成模型连接测试，再在原会话中读取当前文件并继续工作 |

旧设备可以保持应用打开；打包期间仍在变化的数据可能尚未完整进入副本。迁出原样保存目录内容、隐藏文件与符号链接本身，只检查压缩包是否可读取。外部引用与技能链接在迁入时按实际可用性处理，用户无需在迁出时逐项确认。符号链接所指向的外部文件不等于已包含在压缩包中。

设置页按“从此设备迁出”和“迁入此设备”切换，迁出以打开数据文件夹、自行压缩为主要入口，复制打包提示词为可选操作；迁入提供恢复提示词。两种提示词均在浅色卡片内完整展开，复制按钮放在卡片右上角，复制结果直接显示在按钮内。

迁入时，用户在对话中附上 ZIP 或提供本地路径。Agent 在独立目录中解包和检查，列出目标位置、覆盖内容与项目目录，让用户确认覆盖并选择本机目录或跳过。目标应用仍在使用数据时，Agent 完成副本准备并给出退出、放入数据和重新启动的具体步骤。启动时由既有格式升级处理旧数据。只有实际完成并检查后才报告恢复成功。

ZIP 和其他普通文件以附件元数据及实际路径提供给 Runtime，由 Agent 使用现有工具处理。超过附件解析阈值的本地文件保存路径引用，卡片标记“本地引用”，不会复制进会话或自动解析。引用在重新加载和分叉后保留，清理会话不会删除外部原文件；源文件不可读取时按实际状态处理。迁移包中的外部引用不等于已携带文件内容。

## 路径存储

会话索引保存 `directory` 引用，运行时解析得到 `workingDirectory`。相对路径统一使用 `/`，不随设备用户名或数据根目录改变。

| 目录归属 | 持久化形式 | 解析方式 |
| --- | --- | --- |
| Zora 托管目录 | `data` 与相对路径 | 基于当前数据根目录，例如 `workspaces/default/files/<sessionId>` |
| 项目根目录或子目录 | `project` 与相对路径 | 基于所属项目当前绑定的目录 |
| 独立外部目录 | `external` 与完整路径 | 保留独立绑定，失效后由用户选择对应目录 |
| 尚未确定的历史目录 | `unbound` | 用户选择工作目录后保存绑定 |

默认工作区路径由当前数据根推导，索引不再重复保存绝对路径。外部项目保存本机绝对路径，由用户通过“编辑项目”修改。附件沿用已有资源标识和存储规则；历史正文、记忆与工具输出保留原文。

因此，升级后的 `workspaces.json` 仍可能包含 `/Users/bytedance/...`。这些字段记录外部项目原先的位置，目录尚未在本机重新关联时保持原值。用户在“编辑项目”中选择新的文件夹后，该项目的绑定才更新为所选路径，项目内会话的相对目录随之解析到新位置。

例如，托管目录保存为 `workspaces/default/files/<sessionId>`，换机后自动基于新的 `.zora` 定位；外部项目原来位于 `/Users/bytedance/code/project`，用户可以将其绑定到 `/Users/hoshea/Projects/project` 或其他实际位置。格式升级根据目录归属转换引用，不批量替换用户名，也不修改技能软链接的目标。

来源路径按原系统的语法解析，包括 Windows 盘符、UNC 路径和 macOS 路径。工具执行前解析到本机实际目录；外部目录不会仅靠替换用户名推测新位置。

## 数据目录组织

```text
.zora/
├── data-format.json                 数据格式版本
├── workspaces.json                  项目索引与本地绑定
├── config/
│   ├── providers.json
│   ├── default-model-settings.json
│   ├── mcp.json
│   ├── memory-settings.json
│   ├── vision-settings.json
│   └── feishu.json
├── state/
│   ├── skill-registry.json
│   ├── feishu-bindings.json
│   └── feishu-dedup.json
├── workspaces/                      会话、附件、托管文件、定时任务与原生会话
├── skills/                          技能目录或链接
├── memory/                          记忆与每日记录
├── .claude-plugin/                  Claude 技能接入文件，应用自动生成
├── logs/                           运行日志
└── backups/                        历史升级备份
```

六份配置归入 `config/`，三份应用记录归入 `state/`，文件内容保持原样。应用通过统一路径定义读写新位置。其他数据目录及项目、会话 ID 保持原有组织；历史测试文件保留原位。

## 历史版本升级

启动时先完成格式检查，再加载配置和启动业务。`data-format.json` 记录当前格式版本 `2`。

- 无版本标记的数据先升级到版本 `1`：将可确认归属的内部绝对路径转换为目录引用，保存原索引到 `backups/directory-format-v1.json`。
- 版本 `1` 升级到版本 `2`：将根目录已有的九份配置、记录归位，保存转换前内容到 `backups/directory-format-v2.json`。新旧位置内容不同则保留两份并报告冲突；内容一致时保留新位置。
- 每一步在写入前保存 `data-upgrade.json`，全部成功后更新版本并删除临时记录。失败时恢复原内容，重启后可继续；已完成的版本不重复执行。

已升级数据整体移动后，托管路径继续根据当前数据根解析。会话正文、技能内容和外部路径不参与用户名替换。较新的未知格式要求更新应用，保留原数据。

| 文件 | 保留规则 |
| --- | --- |
| `data-format.json` | 正式格式标记，需要随数据保留；删除会重新触发升级判断 |
| `backups/directory-format-v1.json` | 版本 `1` 升级前的索引备份，成功后的日常运行不依赖它，可按需删除 |
| `backups/directory-format-v2.json` | 版本 `2` 归位前的配置和应用记录备份，成功后的日常运行不依赖它，可按需删除 |
| `data-upgrade.json` | 中断恢复记录，升级成功后自动删除 |

只有存在待转换文件时才生成对应备份；备份覆盖该次转换内容，不是完整数据副本。空的 `backups/` 文件夹可删除。`workspace-binding-operation.json` 沿用项目关联操作的临时恢复规则。

## 项目与技能行为

项目目录无法读取时，项目显示为灰色，历史会话保持可读。新建会话图标禁用，悬停显示“该项目文件夹已被删除或移动”。

已有会话仍可发送消息，讨论历史问题并使用可访问的附件。依赖失效目录的文件读写和命令在工具执行时检查。运行时使用会话自身的临时目录启动，保留原项目绑定，避免把临时目录当作项目文件夹。

项目菜单提供置顶、编辑项目、打开本地文件夹和移除项目。“编辑项目”同时修改名称与本地目录，保存后沿用原项目及会话身份，项目内相对目录随绑定更新。“移除项目”保留本地文件夹及其中的文件。

历史独立目录不可用时，文件面板提供“选择工作目录”。同一目录所属的父子会话同步更新绑定，运行中的会话结束后可修改。

| 技能状态 | 加载行为 |
| --- | --- |
| 实体目录或链接目标可读取 | 正常加载 |
| 目录或链接目标不可读取 | 跳过单项，保留目录或链接，其他技能和应用继续可用 |
| 内置技能位置没有任何目录条目 | 初始化该技能 |
| 内置技能位置已有断链或其他条目 | 保留现有条目，跳过初始化 |

## 验收

- 九份配置和记录归位后保持内容，重启保持版本 `2`，升级失败可恢复，新旧文件冲突不覆盖。
- 旧版索引升级后，历史、托管目录及附件关联保持，重复启动不重复转换，写入失败可恢复。
- 整体移动数据目录后，真实 Provider 产生的会话能继续回答历史问题，并通过工具读取新位置文件。
- 项目失效时历史、草稿和旧会话对话可用，工具阻止访问失效目录；编辑目录后，Pi 和 Claude 在原会话读取新目录内容。
- 有效技能链接正常加载，失效链接保持原状，启动不因单个技能失败中断。
- 通过真实界面提交 ZIP，Pi 与 Claude 使用正式 Provider 解压、读取中文文件并重新打包，输出内容与原文件一致。大文件通过本地引用添加和移除，原文件保持。
- Mac 与 Windows 的路径语法在转换中正确处理。四种迁移方向的完整验收还需在对应真实目标系统执行。
